# Graph64 四节点复验

已完成的单节点 `.674` 全部 8 卡、32 臂、128 个驱动样本均通过，`.675` 独立确认清场。本范围选其余 O01 节点，两父作业各选两台，首选 `1087656/f12r3n17,f12r3n18` 和 `1103606/f12r2n10,f12r2n11`。可在同一父作业的 O01 节点中替换。每台都要经该轮实际新鲜零卡探测及现有队列准入，保持已保护或状态未知节点。原先导 `f12r2n13` 不参与。证据见 [原 .674 与 .675](../../../results/bw1000/2026-11-22/O01-BF16-graph64-original674-eight-card-paired-measurement.json)。

worker 相对原先导只改本节点的准入检查。每节点仍用 8 卡、12 CPU、64 GiB、相同 Torch/HIP 和 140 秒 Slurm 预算，各节点一个独立 task。计算保持两个输入和各卡 PCI 派生 seed、M184/K4096/N1024、BF16、64 GEMM/组。两父作业分别运行一个 2 节点 Slurm 步骤。没有集体通信、额外 DMA 或新增设备工作区。

根完成共享签到及资源占用复核后，可由 `package.prepare(publication, campaign_epoch, selected, before_snapshot_SHA256)` 得到 immutable plan、有限发送代码和必须核对的普通发布成员。selected 的每条含 `parent`、`zone: O01`、八个实际 `PCI` 和 `before_CPU_step`。该函数只读本机文件。所有节点使用同一个原 epoch +60 秒和相对 0、12、24、36 秒的四个 8 秒臂，worker 截止 +125 秒；预热、capture、等待、独立数值校验沿用原口径。超过迟到界按原计划缺失。

目标已安装目录中的 `controller.py --reconcile` 只读两条原 Slurm 步骤、四份节点意图和原节点独立报告，每节点仍核 8 个真实所有者和 128 个驱动样本。总分母 32 卡、128 臂、512 驱动样本。对每个父作业实际步骤核终态，再取独立零卡清场归还。共享绝对排期用于安排窗口，当前未验证跨节点时钟误差，也未给出同时计算的群集范围结论。
