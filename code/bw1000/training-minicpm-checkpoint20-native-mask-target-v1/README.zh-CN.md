# MiniCPM 检查点 20 原生 Dropout 掩码诊断

原步骤 `1103606.2303` 的 Flash 和 math-only 对照各有 8/8 个 rank 的最终 RNG 一致，但各只有 3/8 个 rank 的重复 loss 逐位一致。本诊断保留原 Flash 路径，在同一份真实检查点、输入和梯度累积位置上做四臂对照。

- `u1`、`u2` 使用原生前向并记录相同的运行上下文。
- `c1`、`c2` 记录同一次原生调用返回的 186 个 LoRA Dropout 掩码。每 rank 最多持有 512 MiB 实际掩码设备存储，前向及 profiler 退出后才复制到主机，保存摘要、形状、步长、字节数及复制耗时。
- 每臂启动独立的八个 rank，只执行第 20 步恢复后的首个 microbatch 前向。合计 32 个计划前向，0 次反向和参数更新。核对原输入、恢复状态、初始 RNG、真实算子路径以及根模型、语言模型和首个 Linear 的 autocast 上下文。缺失或无效 rank 继续保留在 32 的分母中。
- 比较两次观测臂掩码和 loss，以及原生前向自身的波动。若观测器启用后波动消失，记录观测可能改变结果。诊断与正式恢复、性能和留出集验收分开登记。

使用项目固定 Python 运行 `prepare.py <新的私有目录>`，以已发布的原控制器和掩码观察器生成目标目录及 SHA-256。运行 `check_local.py <同一私有目录>` 核对命令、实际源依赖和 CPU 记录夹具。

目标端先对生成目录执行 `host_once.py --asset-preflight --source-sha256 <生成清单的 SHA-256>`。该入口核对固定的 14 个检查点成员及原生训练输入命令，检查独立试验目录和三个 Slurm 标签，提交 GPU 步骤数为 0。设备准入和一次性试验另由协调者绑定当前父作业、前任保底、设备身份和独立放行收据。保留现有保底，直到实际交接条件齐备。
