# O01 两父作业 BF16 依赖回放深度对照

原八卡试验 .810 独立清场后实证，同样的两条输入拷贝、投影和下游消费链，图回放相对直接提交的有效行吞吐中位数为 2.334 倍。图回放两个局部窗口的驱动忙碌率约 34.25% 和 34.29%，直接提交约 24.84% 和 24.03%。此前没有分开记录同步等待和事件读取，因果归属仍待核实。

本轮同一进程内测量每次回放 1 对和 3 对，顺序为 1、3、3、1，四个固定 60 秒臂。每对在两条固定 lane 上执行 BF16 D2D 拷贝、M186/K4096/N1024 V 计算和 8×186×128 的稠密因果概率×V 消费。两种深度按同一逻辑顺序交换正负输入；3 对图的两个入口分别执行正负正、负正负，1 对图的两个入口分别使用正、负。交替回放前后核对不同输出槽，并在捕获后修改同地址原数据，核对完整 BF16 投影、独立 CPU 投影前 16 列和两种符号的全量 CPU 消费者参考。两臂使用同一批驻留张量，计数按完整对、链数、有效行和 D2D 字节展开。

正式测量记录完整臂主机墙钟、提交、同步等待、事件查询及 GPU stream 事件包围时间。前三项是分开的主机时间片，事件包围区间与同步可以重叠。驱动忙碌率来自时间窗内 12 个合格读数。它与每秒有效行的分母不同。窗口内只证明发布的代理工作，不能给出独占 GPU 执行时间。准备期另记两种图捕获成本、首个回放、原三段诊断事件及显存边界。正向吞吐差可用于估计收回额外捕获成本的对数，单模型和完整训练仍需独立验证。

固定节点池为 O01 的 f12r3n17/f12r3n18（1087656）和 f12r2n10/f12r2n13（1103606）。每父作业需有至少一台完全通过新鲜 PCI/KFD/PID、Slurm 和队列准入的代表节点。动态保留实际就绪的训练、推理和原请求。原五台 f11r4n09/f11r4n10/f11r4n19/f11r2n15/f12r2n12 继续排除。最多两步、4 台、32 卡、128 臂、1536 个驱动样本。不同父作业只在各自本机窗口解释读数。T09 和原 Kimi 节点均位于本轮 O01 范围之外。旧结果不会替代新鲜准入。

原 epoch 加 0/20 秒允许两批分别开始准备，加 82/112 秒进入首臂。worker、Slurm、控制器预算为 390/415/450 秒。根协调者发布精确包与认领，使用 launch.ship(publication, snapshot, transport, requested=None) 一次。传入节点集合时要求请求集合全部通过且覆盖两父作业。已发布目标控制器的 --reconcile 和 --inspect-stop 沿用原受控编号步骤和独立收据。终态与独立清场闭合才能释放预约。

在此目录运行 python -B -X utf8 test_replay_depth_CPU.py -v。本机检查使用模拟硬件调用和临时队列。更大范围需实际首轮算子数值、吞吐、准备成本及清场证据。
