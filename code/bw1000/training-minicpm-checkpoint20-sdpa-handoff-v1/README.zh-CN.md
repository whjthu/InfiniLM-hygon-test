# MiniCPM 诊断接棒

此入口将同一训练节点上已确认归属的 BF16 保底步骤 `1103606.2208` 交给已部署的 MiniCPM 诊断。执行前先通过普通 Git 发布，并由专职监控协调唯一交接。先复查原资产、新请求名称、节点归属及保底记录。如果保底仍正常运行，只向其原 Slurm step 发一次 TERM。原保底进入结束流程时继续观察同一编号。

只有在独立记账确认原步骤终结、原 worker 正常返回且节点没有其他编号步骤时，才会启动原诊断控制器。GPU 作业之前，原控制器仍会独立核验物理设备和端口。控制器提交及终态以原作业账务和现场记录为准。交接失败后先核实原目录和实际步骤，再决定是否恢复保底。

本机用 `check_local.py` 验证单次发信号、自然结束、竞态、归属错误、重复命名空间和截止时间的处理。执行 `handoff.py --handoff-publication <发布提交>` 是真实交接，会改变 Slurm 状态。
