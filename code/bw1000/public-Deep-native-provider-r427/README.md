# Deep public Native provider

This package connects the ordinary public `InferenceServer` engine factory to the qualified Deep afc6 Native engine. It is source/recording-CPU delivery, not a new Model, device, HTTP quality or performance qualification. `execute_authorized` and `Model_READY` are false in the template. No job or model load is included.

The concrete path is `python -m public_deep_native` → source/config verification → pinned public processor and server → public lifespan → `DeepProvider` → one engine-owner Python thread → actual Native create/raw load/finish → prepared FIFO → original Native forward and autoregressive continuation → reset/drain → Native destroy. The Native engine itself creates eight Runtime workers; this is not eight Python processes or a callback-only model stub. The real model type is `deepseek_v4`, TP8/PP1, one static row, capacity32768, BF16 outputs and the original precision5 policy. The only accepted Native is afc6 with HC0. HC1/976f and the router candidate are not defaults.

The public source is a read-only dependency on `public-GLM-native-provider-r425`, manifest122b69d7c1571f1523e15c672839e2d4479e91863e80018b4a8bb60c2ce93724. Only its generic public Python tree is imported, not its GLM provider. Five prepared queue/bridge/history files are copied byte-for-byte. Their actual hashes and original forward AST provenance are recorded in `DERIVATION.json`. The frozen425 package is unchanged.

`checkpoint_loader.py` consumes all67569 actual Native keys through original safetensors CPU tensors, keeps strong references until each Native load returns, uses the original1024-tensor/512MiB bounded batches and calls finish. It checks the actual checkpoint config/index hashes. `forward.py` contains the original d206 forward body as static source, including all existing policy/counter checks; it does not execute a source fragment at runtime. `native_decode.py` retains complete1024-token prefill, discards intermediate chunk samples, emits the final prefill sample, then feeds actual Native sampled tokens until EOS/budget/cancel. Full history and prompt+budget capacity checks remain in the prepared queue. No benchmark fixture, fixed request count, synthetic model type or alternate HTTP application exists in the production path.

Native operations and all resets/destroy run on the one owner thread. Public stop closes admission, marks active requests canceled, lets the current Native call return, then resets/drains before completing pending cancellation. Error paths fail requests and destroy the engine. There is no automatic replay/reload. If a Native owner cannot return by the original process cleanup deadline, this explicit provider terminates its own public process rather than canceling a Native thread. Actual Native destroy status and optional `/proc` thread-exit observation are recorded separately.

Deployment requires the existing qualified Deep container/environment: all eight claimed GPUs, the original binding/DTK/SDK/Common files, BLAS-policy preload, `INFINILM_OWNER_CPU_WIDTH_R2392=4` and at least32 allowed CPUs, the real `SLURM_JOB_ID.STEP_ID`, original MoE tail/prefill-pack flags0 and no private trace/position-proof options. The same provider paths are verified before weight loading. The original create>8GiB and postload/request>=16GiB free-memory floors are retained. A future device claim must separately bind its node, original epoch/deadlines, config/source manifests, environment, port and cleanup controller; the template is not permission to load.

`--config ... --config-sha ... --source-sha ... --run ... --actual-step ... --gpu-start-epoch ...` without `--serve` validates source and deployment schema without importing Native or accessing devices. `--serve` additionally requires explicit execute authorization, node/Slurm identity and the qualified source/provider closure. Uvicorn serves the actual public app and the original absolute service deadline shuts down admission and the owner. It does not run a benchmark client or manage Slurm.

`check_CPU.py` executes the actual public constructor/lifespan, new provider/actor/worker, loader, forward and decode functions with explicit recording leaves for Native CAPI, checkpoint tensors, Torch/devices, ELF/proc identities, official processor tokenization and FastAPI construction. It covers all67569 key descriptors, tensor-borrow lifetime through load, all four dtype codes, bounded batches, complete multi-chunk prefill, Native sample/EOS, active cancellation that waits for Native return, nonzero Native fail-stop, one destroy and owner-thread exit. It also calls the actual source-only CLI and verifies the frozen public dependency. These leaves do not prove Rust-tokenizer behavior, actual8-device owner lifetime, real weights, HTTP transport, numerical quality, throughput or Model readiness. No Native library is loaded, no weights payload opened, no GPU/job/compiler is invoked.
