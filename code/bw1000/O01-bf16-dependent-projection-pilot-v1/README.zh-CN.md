# O01 BF16 依赖链试验

固定到父作业 1103606 的 O01 节点 f12r2n13，使用 12 CPU、65536 MiB 和 8 DCU。只有当前无编号 Slurm 活动步骤、设备清单和八张 PCI 一致、KFD 和设备文件进程均为零，且当前训练、推理或其他原预约未保护该节点时，才能预约。固定排除原有五台节点，当前范围没有自动替补节点。

同一组确定性数据执行两条相同的依赖链。每条先把当前输入拷到常驻 BF16 slab，再用 M186/K4096/N1024 做无偏置 V 投影，最后对真实布局转换后的 8×186×128 张量执行稠密概率×V 消费。两臂均有相同的输入拷贝、投影和矩阵乘；区别只在使用直接提交，还是对两条链只调用一次图回放。概率为确定性因果输入，每个 KV head 使用一个概率组。形状取自 T01 原投影，消费者覆盖依赖路径，模型的完整注意力、训练更新和模型速度仍需各自验收。

准备期记录两条链的输入拷贝、投影及消费者事件，图捕获时间和两臂首次完成时间，以及三个 HIP 显存边界读数。三个读数许可保留显存下限，采样间隙峰值待另行测量。用 CPU 参考核对投影前 16 列，比较两份完整 BF16 投影，并对整个消费者输出做独立 CPU 加权参考。捕获后改变源输入符号，重复核验实际消费者，防止回放拿到陈旧结果。

正式相同计时口径为直接、图、图、直接，4×60 秒。每个完整两链提交计 2 次输入拷贝、2 个投影、2 个消费者。阶段探针和数值回读在计时窗外。八张卡共有计划 32 臂、384 个实际驱动读数。首次计划工作在原 epoch 加 82 秒，worker、Slurm、控制器分别在 350、365、400 秒预算内。独立 reader 比较每卡两组的有效行速率，按各组稳态时差估计覆盖实测图构建成本所需提交次数。没有每次提交节省时，回收次数未定义。

根协调者发布精确源和认领后调用 launch.ship(publication, snapshot, transport, requested=["f12r2n13"])。传入当前一次独占已授权传输与新鲜实际准入收据。仅允许一个原工作请求；不明确时对同一 controller.py 执行 --reconcile。停止检查只接受原编号步骤和该节点原 worker 的信号处理器证据。终态和独立清场均过后再释放。

在当前 Python 下执行 python -B -X utf8 test_pilot_CPU.py -v。当前准备限于本机验证与源码，实际硬件数值和性能尚待试验。实机八卡资格完成后才评估扩大范围。
