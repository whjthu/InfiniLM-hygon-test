# T12 VGGT 三段录制九对输入训练与恢复

新的唯一原请求是 7b07ac6c8bd3e86e63e7528fd1c885f0。固定父作业 1103606，节点 f13r4n09，4 CPU、64 GiB、1 DCU。旧 c556 和旧 bidirectional30 均保持原执行。数据使用目标已经安装的九对公开 RGB-D 原件，沿用 a68952c 的 393 个共同文件及原六个覆盖，模型与 DTK/Torch 复用原成功 T12 环境。此次无需导入新的媒体或覆盖目标预检候选。

派发前绑定实际原 .922 CPU 结果、.923 独立清场、实际安装凭证和九对内容。目标 HOST 重新比对已安装的 398 个候选成员和原 bundle 后只读挂载，原 Torch 数据调用在训练过程中使用同一批次、几何和输入顺序。CPU 前置范围不计训练更新。

单个原 GPU 步中先用原 seed 20260911、常数 LR 2e-5、每步两帧、冻结 aggregator、训练 camera head 的九对配方完成 25 次更新。真实保存第 10、20 和 25 步。随后启动新的 Python 进程，从连续臂真实的第 20 步检查点恢复，再运行 5 步。恢复只校验相同后续输入上的步数、数据游标、loss、梯度范数、参数、优化器与放置、RNG 和完整终点状态。共计划执行 30 次更新，其中 25 次用于连续训练证据。两种运行只在恢复方式上变化。此范围使用 TUM 数据，正式 CO3D、A100 同配方性能和留出指标另行验收。

运行期间 1800 秒、GPU 1440 秒、容器 1300 秒；由目标控制器分配同一个原 epoch，phase 从同一截止时间扣减。根协调者使用 launch.ship(publication, snapshot, transport) 绑定最新一次设备准入、精确已发布字节及共享直接预约。原始目录已存在、原状态未知、同节点有高优先级训练或原预约时保留当前证据。正式结束还要确认本次实际 GPU 和独立后置 CPU 清场均通过，再结账。

实机终态由 read_terminal.py <原结果目录> --actual-accounting <pre/gpu/post 三个实际七列登记> --independent-post <独立 CPU 准入格式收据> 核验。调用方须提供原终态之后实际取得的收据。读取器重新计算从两份真实原 worker 回执得到的恢复结论，并保留失败时可见的原步记录。
