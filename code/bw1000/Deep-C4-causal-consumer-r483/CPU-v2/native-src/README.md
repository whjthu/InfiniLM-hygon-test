# Deep483 guarded input owner source v2

This is a new immutable source revision of the real C4 probe. CPU1122/source-v1 and Native90ba remain unchanged. The same13 C ABI signatures and exact Python binding bytes are preserved. No target container compile, Native load, checkpoint range read, SDK call or GPU experiment has run for v2. GPU_GO and Model_GO are false.

Each actual checkpoint/input upload allocates one flat Tensor in its real dtype, with256 bytes before and after the payload. A contiguous narrow/view at the original shape points into that actual allocation. The full flat bytes are uploaded. After the real load or C4 prepare returns, the probe synchronizes, copies the complete flat input storage back and checks prefix, input payload and suffix byte for byte. Prefix A5/suffix5A are private guards. This detects changed inputs or guard writes; unchanged guards do not prove absence of every out-of-bounds read or complete operator correctness.

Heap-owned host buffers and actual Tensor owners survive asynchronous copies and normal/exception drain. A failed audit poisons the wrapper through its original invoke path; close remains available. Counters advance only for successfully audited buffers. Native prepare timing stops before the audit; input_audit_seconds includes its sync/D2H/verification. Full CAPI/schedule wall retains all additional costs. New guards add512 device bytes per input, plus host expected/readback buffers and whole-input D2H. They are not free and must be identical in future OFF/ON arms. Do not compare this instrumented allocator or timing with CPU1122/no-input-guard baseline as a performance win.

The shared input_guard.hpp is standard C++ byte/shape/overflow logic. The local Windows g++8.3 C++17 unit test passed6 valid cases and rejected42 corrupt/invalid cases, including first/last bytes of both guards and payload, truncated/extra copies, invalid dimensions and overflow. It also handled the current largest8MiB checkpoint payload and a full4096-row hidden input without reading actual weights. This validates only shared host logic; it is not target g++11, actual Tensor narrow/view, D2H, driver floor, numeric, lifecycle or device qualification.

verify_source.py verifies the exact source-v1 pin, unchanged binding and13 exports, and that changes are confined to Inputs, audit counters and two audit boundaries. The old1116 cache probe already used real flat/narrow/view and D2H guard checks; this revision reuses that API pattern without repeating its experiment. The new C4 consumer is a different source scope and needs an exact oneHOST CPU-v2 package, private quote origin, fresh-M/MD and new header pin before target compile; do not replay1122/1113/1116 or claim their qualification for this source. Independent invalid/stale/foreign Native guards, full compressor numeric reference, seven actual range pins, complete device claim and single epoch remain prerequisites. No service was renewed and original906 reservation remains held.
