# DeepSeek inverse RoPE 的 64 位对齐前缀搬运

固定 TP8 单 token 的 BF16 `[1,8,512]`、F32 角表 `[1,64]`、每头一个 64 线程 CTA。输入和输出都按 8 字节对齐时，按四个相邻 BF16 一组做 64 位拷贝。只有 4 字节对齐时走已冻结的 32 位逻辑，只有 2 字节对齐时逐 BF16 搬运。8 字节对齐路径的每头组数由 224 降为 112，逻辑搬运仍为每头每方向 896 字节。尾部 64 个 BF16 的逆旋转代码逐字节一致。

本机 GCC 8.3 的两个拷贝 probe 分别产生两条 `movl` 和两条 `movq`。实际运行覆盖 18 个对齐用例、15 个混合对齐回退和 11 个拒绝用例，逐值比较 8,676,864 个前缀值与 1,239,552 个旋转值，输出 guard、输入、角表、stream、CTA 数及两个返回码均通过。目标算子指令、时间和端到端性能仍待实测。

已生成相邻目录中的单 TU gfx936 源码和 worker。目标先用实际设备工具链验证 64 位与 32 位指令、寄存器和溢出，再对已冻结的 32 位候选做同卡数值和三组暖态配对。产物取得实际 SDK、ABI 和设备数值资格后，才能接入现有调用方。

```text
python -B check_local.py --compiler <GCC executable>
python -B render.py <new-target-directory>
```
