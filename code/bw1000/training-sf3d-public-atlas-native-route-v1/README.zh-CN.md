# SF3D 公开两对象训练路由

新数据配方通过共同框架的 Stable Fast 3D 训练入口显式选择 `sf3d_atlas`。运行参数中的 `sf3d_atlas` 包含 train-only 清单的绝对路径、字节数和 SHA256。标准入口继续选择原后端。新路由在启动 CUDA 前核对 WaterBottle、Corset 的顺序、图像和标签；BoomBox 开发对象只留在评估数据中。

新后端从冻结的原生 SF3D 实现生成，原生场景编码、三平面查询、图像特征、损失、优化器和完整恢复仍使用原调用。新标签在原特征准备流程中构成监督目标。训练图像、标签和输入模块的摘要进入配置哈希，原检查点验证使用这个新哈希。

本机验证从真实数据生成 train-only 清单和三个文件的源码覆盖层，执行共同 CLI 原路由和新路由，后者在 CUDA 边界截停。包含开发组的清单、相反输入顺序和错误清单摘要均在该边界前拒绝。本机实际 CUDA、权重、原生特征和优化器调用为零。

发布源是 `render.py`、`atlas_inputs.py` 和本机复核入口。运行 `python -B render.py --output <new-directory>` 生成源码覆盖层。后续部署使用冻结框架和该覆盖层，训练图像、标签和组合清单保存在项目私有存储中。
