# 空闲 DCU 保底

保底用固定 BF16 矩阵乘法占用空闲设备。一节点对应一个可中断 Slurm 步骤。生产窗口按节点由同一请求稳定错开在 175 至 180 分钟，Slurm 硬上限最多再留五分钟。每张卡先验证固定乘法结果，再记累计实际调用数和驱动读数。纯占卡、有效业务和训练储备分别统计。

监测员用当前 Slurm 两个父作业的实际编号步骤发现空闲节点。重新取得同轮 PCI、KFD、进程及端口收据后，调用 dispatch.py 防止重叠待对账工作和可派发训练，再通过既有认证通道调用 controller.py。远端用共享互斥锁串行创建自己的保底步骤，并在派发前复查父作业和活跃步骤。

status.py 只读检查一个实际保底请求，以独立 Slurm 记账核对活的步骤、每节点八卡和每卡近期实际计算记录。同步全池利用率另用 tools/collect_training80_busy_pulses.py 的零卡采样。单卡进度和异步驱动读数不计入同步全池结果。

要交接高优先级任务时，核对保底独立编号步骤、父作业、节点和原收据，经 Slurm 结束该步骤后再独立确认 PCI、KFD 与相关进程清理。空闲且已经准入的节点可独立补位。无法查看设备进程或仍有活动持有者的节点继续排除，保留原样本分母。
