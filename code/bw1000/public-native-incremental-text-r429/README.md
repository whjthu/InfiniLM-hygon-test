Explicit optional text-stream consumer for the existing Native bridge.

The current P0 consumer ignores progress text and decodes once after Native
finish/reset. The new mixin decodes complete visible-token prefixes, emits safe
text before final finish, holds trailing Unicode replacement characters, and
fails on changes to previously emitted text. The same NativeRequest, FIFO,
abort intent and Native reset/finish ownership are retained. No second engine,
installed-module patch, Native math or default selection is introduced.

Select only by explicit class composition in a future prepared factory. The
current425/427/428 providers are unchanged; this directory alone is not a
working public deployment. Native progress can coalesce, so one text delta is
not one output token and may not be expanded into invented client token times.

Eight local tests execute the new mixin with original production bridge and
NativeRequest. The byte tokenizer and owner actions are recorded leaves. The
separate bounded CPU claim checks the actual pinned GLM tokenizer on every
prefix of all128 original418 outputs plus three Unicode controls. Original
IDs remain only L/R. Input encoding844 and the128Modelrequests are not rerun.

Even a successful CPU result does not qualify the actual public parser/HTTP,
Native lifetime, Kimi/Deep tokenizer, online arrival load, or user speed SLO.
The mechanism is defaultOFF until a later explicit consumer and real service
validation. No GPU is claimed or launched here.
