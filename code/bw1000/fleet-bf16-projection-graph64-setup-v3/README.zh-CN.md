# Graph64 v3 固定窗口的节点就绪对照

v2 有三台节点的 24 个 owner 在首臂之前报告 BrokenBarrierError。原有 8.50–14.55 秒的单 owner 设置耗时缺少各线程到达屏障的同一时间基准，无法定位先超时、进程启动较晚或 owner 提前退出。v3 在相同组内观察三台原失败节点及三台 v2 已通过的节点。

| 父作业 | 区域 | v2 失败 | v2 已通过 |
|---|---|---|---|
| 1103606 | T09 | f13r3n13 | f13r3n14 |
| 1103606 | T10 | f13r4n05 | f13r4n06 |
| 1103606 | T11 | f13r4n08 | f13r4n07 |

固定主组共 6 台 48 卡，按原 3 个同父同区分片派发。可由根明确追加已经通过当次 Slurm、PCI、KFD、PID 和共享队列准入的 v2 未覆盖节点。它们另计实际覆盖，原请求未对账和当前设备有持有者的节点继续等待。

| 父作业 | 区域 | v2 未覆盖节点 |
|---|---|---|
| 1087656 | T05 | f11r4n09、f11r4n10 |
| 1087656 | T11 | f11r2n15 |
| 1087656 | T12 | f11r4n19 |
| 1103606 | O01 | f12r2n12 |

同卡 BF16 M184/K4096/N1024、64 GEMM、两组真实 resident 输入和前 16 列 CPU 数值核对沿用 v2。计时仍从原统一 epoch+60、+72、+84、+96 秒启动 eager、graph、graph、eager，各 8 秒。owner 必须在首臂前 2 秒完成设置并汇合。每一臂在原固定开始前 200 毫秒关闭独立的就绪门，之后由原测量器按固定窗口采集。设置持续时间、设置与逐臂门的首末到达与首发故障单列。私有每卡设置收据在设置门之前落盘，落盘成本计入设置预算。四臂、采样、正常释放和独立清场仍分别验收。

根协调者通过普通发布后的 `launch.py:ship(publication, snapshot, transport)` 使用新请求。可选参数 `requested` 必须明确给出固定 6 台和要附加的已准入节点。任何所选节点当前无法安全准入时，保留完整比较范围并重新取得证据。独立追加尚未覆盖的组不得代替比较组。需要为新原计划另行绑定终态、同父清场和共享队列结账。该源准备未产生实际 Slurm 步骤、GPU 数值或训练结果。
