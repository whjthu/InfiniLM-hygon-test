# Deep public SSE default incremental delivery

Run the isolated ordinary provider with `python -m public_deep_default_text --config ...` using its published source/config hashes and the existing bounded deployment identity arguments. `--serve` still requires a separately authorized concrete resource claim. Source-only invocation validates this schema without Native or weights. This package uses the same actual public InferenceServer, prepared engine factory, afc6 HC0 TP8PP1 provider, loader, Native loop and cleanup as qualified427/430; it creates neither a substitute model type nor a second HTTP app. The original430/429 source remains immutable.

Default policy in this new provider: absent `text_delivery` selects P1 only when the actual request `stream is True`; false or absent stream selects P0. Explicit P0/P1 takes priority. Other explicit values are rejected before admission. The original public prepare_agent_request preserves stream and validates its boolean type; its same returned data reaches both the public sampling validation and add_chat_request. No field is reconstructed from a different request.

The CPU consumer executes the original nested public chat_completions route body and original sampling, parser, JSON and SSE method bodies. Decorators/unused full server construction, HTTP Request/transport and Native owner actions are explicit recording leaves. It uses the actual Deep processor, Rust tokenizer and parser against two original complete bodies/outputs. It tests only the new default/override/rejection and abort-intent branches, not the old nine-case/all-prefix suite. Legal Torch import is recorded; mapped project Native libraries, device initialization and weight reads are forbidden.

The existing430 device run qualified explicit P1 only. It showed earlier reasoning delivery, not Native or full-request speedup, answer-content improvement or a15tok/s client SLO. This source/default CPU card grants no new GPU or Model execution, and the new default is not described as device tested.
