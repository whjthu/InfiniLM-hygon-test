# Graph32 与 Graph64 分批持续对照

- 同一组常驻 BF16 输入、权重和输出，使用 T01 前向投影的 M186/K4096/N1024 几何。四个 60 秒窗口按 Graph64、Graph32、Graph32、Graph64 排列，按每秒完成的有效行比较。操作数由固定种子生成，核对两个完整输出和 CPU 参考前 16 列。
- 原运行 epoch 加 0、20、40 秒开放各批初始化，加 48、78、110 秒开始各批首臂。v3 已通过组优先启动，v4 已证实 setup gate 超时的四台进入末批。随后各臂固定加 64、128、192 秒，错过窗口保留失败与分母。
- 控制端记录启动意图，节点记录进程进入、信号处理器就绪、PyTorch 导入、HIP 初始化、各卡输入就绪和分别捕获的两种图。共同时间由经过独立核验的外部时钟证据计算，启动与热身均未计为有效工作。
- 另设 epoch 加 375 到 435 秒的 Graph64 共同网格。每臂每卡有 12 个实际驱动样本，完整节点为 40 臂、480 样本。overlap.audit 仅在完整节点的已测窗及每节点边界证据均与原终态和步骤绑定、调用方提供验证过的时钟回执 SHA 时，计算保守重叠。资料缺失时保留实际本地数据及分母。
- 使用现有 80 台账本、新鲜 PCI/KFD/PID 准入和 SQLite 实际保护。固定保留 f11r2n15、f11r4n09、f11r4n10、f11r4n19、f12r2n12、T09 f11r4n17、Kimi f13r1n01。最多 73 台 584 卡、2,920 臂、35,040 样本。
- 唯一根入口 launch.ship(publication, snapshot, transport, requested=None)。通过已发布精确源码并提供新鲜真实准入与既有授权传输，才为一次原始请求生成隔离分片。controller --inspect-stop 复核原编号步骤及所有 worker 的处理器，仅返回协作停止命令。释放仍需原终态和独立清场。
- worker deadline 455 秒，Slurm 470 秒，控制器 510 秒。运行 python -B -X utf8 test_staggered_CPU.py -v 做本机验证。本包源编排和计数在本机验证完毕，实机工作与跨节点时钟待实际回执。
