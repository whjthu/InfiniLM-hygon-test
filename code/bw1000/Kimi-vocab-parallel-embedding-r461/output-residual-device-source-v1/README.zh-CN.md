# Kimi 末端残差分块单卡对照

使用实际 Kimi 检查点的 RMSNorm 和投影权重，以及同一份固定的 512×9×7168 BF16 残差输入。输入应标明是受控输入还是原模型激活，原始数据留在海光。每臂使用独立进程和相同的原始权重后处理设置。候选每次处理 64 个 token，完整 softmax 和最终 GEMM 沿用原调用。

`extract_residual.py` 从已在目标端编译的 TextModel 源码生成组件方法。替换范围是方法归属和显式臂选择，组件保留真实 Runtime、RMSNorm 和 Linear。组件入口同步后核对完整残差输入和两侧保护区。计时从设备调用开始，到末端 GEMM 同步返回。加载和回读单列。

`CHECKPOINT_WEIGHTS.json` 记录原文件实读的 28,672 字节范围和校验值。Python 调用方检查权重字节、配置、索引和组件库身份后执行。配对读者比较全部 3,670,016 个 BF16 输出，报告有限性、变化数量、最大绝对差和相对 L2。

驱动显存只在初始化前、准备后和设备调用返回后采样。4 GiB 门槛在这些采样点执行。瞬时峰值、整模型显存余量和逐用户速度仍待实测。
