# Kimi TP32 分块预填充因果对照

调用者传入已加载权重并完成准入的四节点 TP32、PP1 上下文。先运行 256 分块，再运行 512 分块。两臂分别重置同一上下文，使用同一完整提示和两个预先固定的续写 token。每次调用记录绝对位置、`past`、输入摘要、原生返回、四节点一致性以及原 4 GiB 采样下限。调用者可把原首块亲和性检查传给 `after_first_prefill`。

在共有的第 512 个输入位置、提示末尾以及两次续写后保存节点 0 的完整 BF16 词表输出。提示长度等于 512 时，提示末尾与第一个位置合并。原始向量与输入只写私有存储。比较器重新核对两臂调用顺序、输入位置和完整向量 SHA，再报告 BF16 位变化、绝对误差、argmax 与原生采样 token。固定续写对照用于验证可观察的因果延续行为。设备 KV 内存、端到端 TTFT、在线逐用户速度和模型质量各自需要目标实测。

本机用 NumPy 与 ctypes 运行带错误注入的提交通道。另用两个冻结的原 C++ 头编译 T1 至 T28672 的调用计划校验。集群启动与模型加载由既有准入流程负责。
