# Kimi r461 输出残差评分的输入复读

固定 full-tree 评分的 4608 CTA、每 CTA 256 线程和 BF16 输入 `[512,9,7168]`。每个线程按旧列顺序保留自己的 28 个 BF16 词，RMS 和 dot 两阶段复用这些词。原 FP32 加法树、指令舍入、BF16 归一化舍入、最终分数编码和同步顺序保持原样。HOST 组件、Softmax、最终 GEMM 和 C ABI 与冻结 full-tree 源一致。独立候选只编一个 score 对象。

按源码少一次全形状输入值复读，即 66,060,288 个逻辑字节。原 gfx936 编译器是否已跨屏障留存这些输入词尚未知，仍存在的复读也可能由缓存服务。保留数组是每线程 56 字节、每 CTA 14,336 字节的逻辑私有数据，实际寄存器、溢出和设备流量尚未知。原 .340 实测是三组同卡组件配对。原 .337 单臂测到的 3.012320347 秒首次 projection 包含首次调用成本。暖评分阶段成本和本候选速度仍待实测。

```text
python -I -S -B check_local.py
python -I -S -B render.py <new-target-directory>
```

在新目录封存 DTK CPU1113 的工具与依赖来源，沿用原 fresh M、编译产生的 MD、对象及 ELF 符号资格。单 TU 目标预注册资源 4 CPU、8192 MiB、0 GRES、300 秒，实际目标准入要由协调者核对。目标产物为 `retained28/fused_scores.o`，只与对应冻结 HOST 组件单独链接。旧 full-tree/wave32 作业和归约参数不参与此次编译。

本机 g++ 对渲染翻译单元的真实平方和点积 helper 做全形状对照，同时通过旧 launch shim 检查 launch 和状态边界。对照两份实际 gfx936 对象并保存 VGPR 数、每线程 scratch、屏障前后输入读取和 spill 指令。只有确实消除读取且未增加 scratch 或 spill，才进入单卡数值与计时。沿用原权重和冻结输入，完整内部 BF16 score 和最终输出先过同值检查。暖计时采用同卡 AB、BA、AB 三对，每臂 2 次预热和 8 次同步派发计时，启动及回读分列，保留失败分母。初筛要求每对候选暖计时中位数均低于基线，并报告每对与总配对比值。这项门槛仍是组件筛选。
