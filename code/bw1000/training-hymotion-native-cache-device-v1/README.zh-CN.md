# HY-Motion 缓存生产器的 CUDA 与 ROCm 入口

本目录提供统一训练框架中 `generation/scripts/prepare_hy_motion_training_cache.py` 的候选替换文件。基线来自冻结的公共 393 文件清单及归档，原文件 SHA-256 为 `7a8fceef0d4ba30c6676881d3c7dc59fed4c73b54e292d14b57bcdba1c40a203`。合并时先校对该文件身份，再以本文件替换同一路径。

`--device cuda` 使用 PyTorch 的 CUDA 接口，按实际编译后端记录 CUDA 或 ROCm。文本编码、WoodenMesh 及输入均使用同一设备，沿用 BF16。缺可用设备会报错。默认 MLU 路径仍使用原播种、默认帧长与输出结构。

新的 128 帧用例显式加 `--frames 128 --require-full-frames`。生产器要求同样本的 `(F,135)` 与 `(F,22,3)` 源数组帧数一致，输入为有限浮点值，短样本不进入选集。还可加 `--check-source-only`，执行同一源输入选择，输出数量与帧长，不载入模型或写缓存。完整生产时继续采用原 135 维运动输入、WoodenMesh 重算的 66 维关节点和原统计归一化、文本编码及分片格式。

本机 `check_local.py` 通过 5 项，覆盖原默认可选短输入、严格 128 帧、坏形状或非有限值、命令行 CPU 输入检查、后端选择及原 201 维组装。后端选择测试使用模拟的 Torch 接口。本机没有执行真实 CUDA、ROCm 或 MLU 缓存任务，也没有读取模型权重。公开 CMU 录制继续保留为独立领域候选，重定向到 135 维、真实文本条件及 128×201 缓存均待验证。原正式 60 帧证据保留原口径。
