# O01 双流完成事件对照

原 584 卡分块实验完成 1168 个配对，分块相对单拷贝的吞吐中位数为 0.998266。新实验沿用单次 761856 字节 D2H 和原重叠提交，比较双宿主同步与设备事件汇合。设备汇合适用于宿主在继续处理前同时需要计算输出和锁页内存输入的场景。

基线在宿主依次同步计算流和复制流。候选在复制流尾部等待计算结束事件，随后宿主同步复制流一次。等待排在复制流结束计时事件之后，所以两个设备事件窗的边界在各臂保持一致。两个窗口可能重叠。宿主完整时间包含提交和等待，事件依赖的宿主调用时间另外记录为提交时间的子区间。每单元保持两次图重放、36 条 BF16 依赖链、固定 D2H 字节、相同源和目标、相同归属设备、全量 BF16 和 CPU 校验、双端红区。

每卡绑定原 HIP 动态库里的 `hipStreamWaitEvent` 后，在计时前实际执行一次候选，先污染输出，再复核 BF16 结果及拷贝完整性。正式四窗按基线、候选、候选、基线执行，第五共同窗口保留基线。报表核对事件依赖次数、宿主同步次数和完整工作分母。以每卡完整组的实际 wall 吞吐配对为准，同时保留分开的 event、host 和 driver 数据。

发布和鲜活设备准入后调用本目录 `launch.ship(publication, snapshot, transport, requested=None)`。每个分片按原父作业和分组分配，每步最多四台，每台 12 CPU/64 GiB/8 DCU。保留原五台排除，并为 T12 CP10 保留 f13r4n09。T02 f13r1n12 根据最新设备准入和队列持有状态动态保护。上限 74 台、592 张卡，实际数量随当轮设备准入而定。控制器耗时上限 545 秒，保持协作退出。用新路径下的 `controller.py --reconcile` 核对原始终态，取得独立清场证据后才释放原预约。

`python -I -S -B derive.py` 核验生成源码。`python -I -S -B check_local.py -v` 核验通过实际启动入口派生的有限任务、真实本机队列预留、源文件、计时位置和模拟依赖闭合。HIP 符号和同步行为由目标实证确认。跨节点同步与在线、训练或模型效益分别验收。
