# VGGT near7 双向相机头训练

同一组 7 个 TUM near 物理 RGB-D 对训练 25 次。每个物理对派生正向和逆向两种输入，共 14 个批次槽。前 7 次曝光的方向是正、逆交替，接下来 7 次对每个物理对反转方向。25 步的物理对访问顺序和次数与原 .978 一致，依次为 4、4、4、4、3、3、3 次。正向训练 13 次，逆向训练 12 次。

逆序同步交换图像、深度、内参、有效像素掩码和帧号，并在新首帧坐标系下重算世界到相机外参。沿用在 .498 实际执行过的刚体逆变换。可检验的假设是，平衡帧次序能减轻首相机坐标系下的方向偏差。反转没有增加独立场景、物理训练对或跨域数据。原种子、模型、训练头、冻结边界、精度、学习率、步数与计时边界继续沿用。14 个缓存批次的额外资源成本待实际观测。

根协调者发布并通过新鲜设备准入后调用 `launch.ship(publication, snapshot, transport)`。调用读取来源固定的目录、模型、运行时和 .922 实机 CPU 资格。采用 1103606 / f13r4n09、1 DCU、4 CPU、64 GiB。整个请求 1800 秒，GPU 1440 秒，容器 1300 秒。准入与唯一原 request 由现有 SQLite 调度事务保护。当前交付为本地源，发布与目标 CPU/GPU 验证仍待完成。

独立终态用 `read_terminal.py <原输出目录> --actual-accounting <独立 Slurm 行 JSON> --independent-post <同父独立清场 JSON>`。要求核对三个原编号阶段、训练 25 步、检查点 10/20/25、全部 14 个派生槽的帧顺序，及留出的 far、sitting 两对共 4 个预测槽。缺失训练步和预测槽保留在原分母。两对内部留出只作工程筛查。

原 .608 和 .1038 同一 24 窗口域外开发集均出现实际退化，见 `EFFECT_GATE.json`。只有训练及清场成功后才准备新的独立 Dev24 评估。复用同一个冻结基线、22 个输入对和 24 窗口分母，两个没有输入的窗口及退化预测继续计为失败。若 AUC@30 低于同轮基线、AUC@15 低于同轮基线的 95%，或失败数增加，则停用 near-only 增强路线。缺证据保持未判定。通过该筛查只允许进一步研究，正式 CO3D、性能和训练效果验收仍待各自实测。
