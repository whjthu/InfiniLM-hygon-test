# Fixed-prefix diagnostic residency controller

This source is not execution-ready. It cannot launch until the immutable final
manifest binds the actual new Native CPU receipt, the real input/entry CPU
receipt, context snapshot, config and pin. The future claim must be published
before a fresh membership/live-step/KFD/PID/port check and the single launch.

The entry, rather than HTTP/queue/client IPC, owns one real NativeContext and
terminates after the frozen 0/1/0/1 teacher-prefix diagnostic. Maximum368 original
forwards and the82/83 capture window remain owned by the existing teacher runner.
No fifth pass, additional HTTP request, implicit retry or model reload is added.

The keeper owns only its newly started srun PGID and exact numeric Slurm step.
The original1374 bounded close_owned function and container wrapper are reused.
Failure signals never target the parent allocation. Normal success separately
requires srun0, SlurmCOMPLETED0, the matching original-epoch report, actual eight
Native owner exits and an independent CPU-only KFD/PID/port post check. Unknown
accounting/report visibility is bounded without treating observation loss as
proof that the job died. The global GPU2700s includes loading; keeper3000s includes
cleanup. Controller polling stays15s; interactive root checks do not wait for the
model to load.

Capture changes allocations, stream work and synchronous D2H costs. Even a
successful diagnostic is not Model quality, a fix, a speedup or a service SLO.
Original1374 quality/run failure and forced cleanup remain immutable evidence.
