# O01 依赖计算与固定 D2H 传输

原 592 卡同步频率试验完成 2960 个卡级臂和 35520 个驱动读数。每两个图同步相对每图同步的中位吞吐收益是 3.13%，共同深度 9 局部驱动均值为 97.124%。此轮固定先前的深度 9 和每两个图的计算单元，检查并行派发真实固定拷贝是否能缩短完整计算加传输的时间。

每个测量单位执行 18 对逻辑工作，含 36 个完整的 BF16 拷贝、投影和下游依赖链，以及一次 761856 字节的设备到锁页主机内存实传。传输量对应两份 186×1024 BF16 投影输出的字节数。载荷由独立设备缓冲区生成，在整个测量臂保持不变，用于隔离传输与算子资源干扰。两臂相同流、同一图、相同事件及同步次数，区别仅是拷贝在计算同步前还是后提交。两条流保留各自 GPU 事件窗和主机完整时间。各流事件窗可能重叠，发起顺序只能表明尝试重叠，实际硬件并行程度需要进一步验证。

图复用已验证的两个正负起始分支。每个臂核对完整投影、CPU 前 16 列、全量下游输出，以及原拷贝源、实收载荷 SHA-256 和双端 256 字节 redzone。主机目标每臂先清空。按原计算、投影和消费者次数、实传字节、两条流同步及实际驱动读数留分母。准备期的权重初始化和校验读取不进入正式时间窗。

按原两父作业节点账本和资源分组派发，每步最多四台，每台 12 CPU / 65536 MiB / 8 DCU。保留历史五台和 T02 的 f13r1n12，当前更高优先级原请求、共享队列占用及新鲜 PCI/KFD/PID/Slurm 设备准入都优先。最多 74 台、592 卡、31 步、2960 个卡级臂和 35520 个驱动读数。任何失败保留已完成和计划分母。此范围为代理计算与实传组件，模型训练、在线和全 640 卡验收各自另行核对。

同一卡以串行、重叠派发、重叠派发、串行执行四个 60 秒窗口，第五个窗口采用重叠派发。三批准备在原 epoch 加 0/20/40 秒开放，加 82/108/130 秒进入首个有用窗口。第五窗在加 397 到 457 秒。worker、Slurm、控制器分别限制在 480/505/545 秒。全范围跨节点测量需要独立核对同一步骤的时钟误差和每个样本，缺失时保留本地结果。

根协调者发布精确源码与认领后调用 launch.ship(publication, snapshot, transport, requested=None)。原不明确状态用同一目标 controller.py --reconcile；--inspect-stop 只核对原编号步骤并返回协作停止入口。原终态和独立清场均通过后才释放原预约。运行 python -B -X utf8 test_transfer_CPU.py -v 可复核本机测试。
