# Gemma VizWiz native index target run

This package prepares a single CPU-only native index request for the existing 12 train rows. It reuses the two original training streams, the frozen 800-position view and the processor-only template. The fixed budget is 120 seconds from the authorized request epoch. The requested geometry is one node, one task, four CPUs, 8192 MiB and zero GRES.

## Local replay

`python -B -X utf8 code/bw1000/training-gemma-vizwiz-native-index-target-run-v1/check_local.py local-only/gemma-index-independent-absent-receipt.json`

The fixture uses the actual source bytes and private training streams. It captures the actual runner's rendered command and substitutes publication, placement, execution and accounting observations for this local replay. The resulting receipt records these substitutions, the original stream identities, the planned denominator of 12 and zero native calls.

## Shared host and compute boundaries

1. After the source publication is independently confirmed, use `prepare_packet.py publication-proof --request REQUEST --commit COMMIT --output PRIVATE_PROOF` to read the exact committed bytes against the existing ordinary Git tracking ref. Use `prepare_packet.py packet --output SOURCE_PACKET` to encode the eight source members. The packet excludes the training streams, view, media, weights, and private run evidence.
2. Place the exact published `runner.py` in an approved shared-host bootstrap location. Verify its SHA-256 against the independently produced publication proof before invocation. With Python 3.10 or newer and `-B`, run `install --request REQUEST --packet-sha256 PACKET_SHA --publication PRIVATE_PROOF --publication-sha256 PROOF_SHA`, piping only the source packet to stdin. The stage is created under the fixed project `incoming` directory after exact file rechecks, using one same-filesystem rename per request.
3. Run `build-view --request REQUEST` on the shared host. It reads the fixed original `.2882` and `.2883` training stream paths and applies the exact published view builder. The 345722-byte view becomes active under the private request view directory after checking its 800 positions and frozen SHA. An existing authorized file named `train800-swift.jsonl` can be selected by exact path and must satisfy the same size, digest and row count. Run `readback --request REQUEST --view PRIVATE_VIEW` as a separate action to rehash the installed source closure, original streams, and chosen private view. Keep the returned canonical result and its SHA in the request inputs.
4. After fresh independent CPU placement admission, provide a pinned request-specific placement receipt and a canonical scope file. See `check_local.py` for the exact scope keys and `runner.py` for the placement receipt fields. Invoke `run --request REQUEST --scope SCOPE --scope-sha256 SCOPE_SHA --readback READBACK --view PRIVATE_VIEW --placement PLACEMENT --placement-sha256 PLACEMENT_SHA`. A fresh shared-host check confirms parent ownership, node membership and scheduler state. The runner writes and syncs a durable one-time intent before invoking the original renderer's single `srun`. One request uses one output directory. Every interrupted or ambiguous submission preserves its no-replay intent. The worker then checks actual CPU placement, original runtime and view bytes on the compute node, two original stream/worker identities and the private train media.
5. An independent operator observes the real numeric step for the request-derived job name. With `TZ=UTC` and `SLURM_TIME_FORMAT=%Y-%m-%dT%H:%M:%S`, capture `sacct -nP -j ACTUAL_NUMERIC_STEP --format=JobIDRaw,JobName%100,State,ExitCode,ElapsedRaw,NodeList,AllocTRES,Start,End` to a private file. Invoke `terminal` with the request, original scope and SHA, `--step`, accounting file and SHA, and the original `SUBMISSION_INTENT.json`. If present, use the actual request output's `RESULT.json` or `FAILED.json` for `--worker-result`; use `--index` for that request's `native-index.json` only with the successful summary. The independent check enforces exact node/scope, four CPUs, 8 GiB, zero GRES, original epoch and the 120-second cap before qualifying any index rows. Store the private index in its request directory.
