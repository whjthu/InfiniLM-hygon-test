新请求 `d3373aa5b25240d5b8e04a555bbd38b9` 从同一官方版本的 A100 副本读取。接收端在新目录中复用原请求 `2cb64431972e4c0ea0db1bf69d2ff3cf` 的 4,442,095,616 B。先核对原失败接收终态、持久前缀回执与独立 Slurm `1087656.949`，再以只读方式复制并流式校验前缀。发送端也验前缀，网络传输范围仅为 `4442095616..4995008463`，即 552,912,848 B。原目录和文件保持只读。

收到源端整片 SHA 成功提交、并核对目标整片大小 4,995,008,464 B 和官方 SHA256 后，才封存新目录中的 `model-00001-of-00004.safetensors`。根协调者再执行独立整片审核。程序在本机仅缓冲二进制流，保存回执和计数。传输预算 1800 秒，限速 1 MiB/s，独立审核预算 480 秒。

根采用后只需重封改动后的 CLAIM 和 SOURCE_FILES，普通发布，再以 `relay.run(publication, transport_argv)` 调用。构造器 `transport_argv(role, command)` 使用已有认证路径，为 `source`（A100-26）或 `target` 返回传递同一个远端命令的 argv。成功后走一次 `relay.run(publication, transport_argv, audit=True)`。传输目录已存在或原响应未知时先对账，保留完整原始分母。
